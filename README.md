# T32

**A compact universal timestamp.** T32 writes any moment as 8 base32 characters: a count of atomic (TAI) seconds since the start of 2000, offset so the past encodes too.

```
G0S7G6B1        2026-10-31 03:13:00 UTC, to the second
G0S7G6B1G0      the same, to about a millisecond
G0S7            the 12-day span that contains it
```

- **Length is resolution.** Drop characters for a coarser span, append them for finer time. Every stamp names an interval, never a false instant.
- **Text order is time order.** Byte-wise sorting is chronological, and a prefix is a range query.
- **Uniform seconds.** TAI has no leap seconds, so from 1961 on, subtracting two stamps gives elapsed time.

## Status

T32 is a draft specification, published for public review. It is complete enough to implement and test against, and it will not be frozen until it has been read widely, implemented independently and questioned properly. The path to version 1.0, and from there to a working group, is set out in [GOVERNANCE.md](GOVERNANCE.md).

## Taking part

T32 is at the stage where a careful reader changes the most. You are welcome to:

- **Question it.** Report anything ambiguous or wrong as an [issue](https://github.com/oddurs/t32/issues/new/choose). A sentence that can be read two ways is worth reporting.
- **Discuss the open questions.** Appendix C of the specification lists what is still undecided, from the epoch to letter case. Views are sought in [Discussions](https://github.com/oddurs/t32/discussions).
- **Implement it.** Pass the vectors in your language and add yourself to [IMPLEMENTATIONS.md](IMPLEMENTATIONS.md). Three independent implementations are a condition of version 1.0.
- **Help govern it.** If you would serve on a future T32 working group, say so. Interest expressed now shapes the charter later.

[CONTRIBUTING.md](CONTRIBUTING.md) explains the mechanics. Everyone taking part follows the [Code of Conduct](CODE_OF_CONDUCT.md).

## Development

After cloning, run `scripts/setup` once: it wires the git hooks, installs the site's packages and checks your tools. The Rust and Node versions are pinned in `rust-toolchain.toml` and `.node-version`.

```sh
scripts/task check                              # every check CI runs
cd rust && cargo run --example t32 -- G0S7      # a stamp's interval
cd web && npm run dev                           # the site, at localhost:5173
```

Changes go through [`scripts/agent`](scripts/agent): each one in its own worktree and branch, landing as a pull request.

| Command | What it does |
| --- | --- |
| `scripts/agent doctor` | Checks the tools, sign-in, hooks and working tree |
| `scripts/agent start <type>/<slug>` | Creates the branch and its worktree from `main` |
| `scripts/agent commit "<message>"` | Commits, with the Conventional Commits check |
| `scripts/agent pr [--draft]` | Runs every check, pushes and opens the pull request |
| `scripts/agent sync` | Rebases onto `main` |
| `scripts/agent done` | After the merge, removes the worktree and the branch |
| `scripts/agent list` | Lists worktrees and their pull requests |

[CONTRIBUTING.md](CONTRIBUTING.md) has the details.
